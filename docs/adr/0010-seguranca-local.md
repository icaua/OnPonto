# 0010 — Sessão e proteção do uso local

Data: 2026-10-10. Estado: aceito.

API permanece em loopback. Middleware verifica conexão local e Host literal localhost/127.0.0.1, bloqueia origens não autorizadas e `Origin: null`. CORS permite somente o frontend local 5500 e origens HTTP de loopback explicitadas em ONPONTO_FRONTEND_ORIGINS. Cookie HttpOnly/SameSite Strict, oito horas, token aleatório armazenado por hash em memória; CSRF aleatório vinculado à sessão para mutações. Sessões são efêmeras por processo e limitadas a 2.048. Endpoint GET /sessao/local tem a mesma proteção de origem. Raiz/health e documentação sem dados pessoais permanecem públicos localmente; os demais endpoints de domínio exigem sessão.

Cliente compartilhado inicializa sessão com credentials=include, mantém CSRF somente em memória e renova uma vez em 401. Renovações concorrentes são deduplicadas. Exportação também usa o cliente; abertura de espelhos/downloads usa cookie. Frontend e API usam o mesmo hostname local para SameSite. Não há token em URL/localStorage, conta remota ou envio de empregados a terceiros. CLI confiável local pode iniciar sessão sem Origin; este controle não isola processos com os mesmos privilégios do usuário do sistema operacional. Um único processo/worker local é o desenho homologado.

Uploads genéricos usam a mesma preservação/hash/evidência da importação: máximo 25 MiB por arquivo e 26 MiB por corpo HTTP, cópia exclusiva e remoção somente do arquivo novo pertencente à operação. Colisão jamais remove original existente. Nome de exibição sem caminhos/controles, destino validado na raiz. Anexos sucessivos permanecem append-only. Hash conhecido é verificado no download, servido como attachment/octet-stream/nosniff/no-store; hash desconhecido legado permanece desconhecido.

TXT mantém codificações anteriores, inclusive UTF-16 com/sem BOM. PNG/JPEG têm assinatura/estrutura/dimensões limitadas a 40 milhões de pixels. XLSX valida contêiner antes de parser (100 MiB total/20 MiB por entrada/4.096 entradas/razão 200), sem extração de caminhos; rejeita entradas duplicadas, compressão diferente de Stored/Deflate e DTD/entidades XML, inclusive UTF-16. PDF tem cabeçalho/EOF, limites de páginas/streams/pixels e descompressão Flate limitada (20 MiB por stream/100 MiB total/razão 200); filtros desconhecidos, conteúdo ativo/incorporado e criptografia são recusados com erro explícito. Isto é validação limitada de arquivo, sem renderização, extração de texto, OCR ou certificação de PDF. Contrato de OCR futuro permanece separado.

API usa no-store, nosniff, frame DENY, referrer no-referrer e CSP. Estilos/scripts inline são permitidos apenas pela necessidade dos espelhos atuais (botão window.print); valores de usuário continuam escapados nos templates. Swagger/Redoc preservam suas próprias dependências. Exceções inesperadas expõem mensagem genérica e logam somente classe, sem payload/traceback; parâmetros SQL ocultos. Logs não recebem cabeçalhos Cookie/CSRF nem conteúdo de anexos. Backups automáticos mantêm a política herdada (sete diários/dez pré-migração) somente nos nomes gerenciados; uploads, snapshots/evidências e conjuntos completos não têm exclusão automática. ACL/permissões e retenção de dados pessoais continuam sob administração do usuário do sistema.

Consulta pública [OSV API](https://google.github.io/osv.dev/api/) em 2026-10-10 para 25 dependências fixadas: zero advisories retornados; JSON preservado em docs/seguranca/dependencias-osv.json. Não se enviaram dados pessoais. Ausência de advisory não certifica segurança; binário Python do instalador e SO não são pacotes PyPI desse levantamento. Distribuição binária permaneceu preservada, conforme escopo.

Testes: HTTP real sem sessão/CSRF/origem/Host, sessão trocada/expirada, preflight, limite pré-parser; PDF/PNG/TXT adversariais, ZIP, UTF-16, download adulterado e travessia, colisão, rollback e restore com hash adulterado. Cliente JS testa sessão compartilhada, 401 e renovação concorrente. Navegador usa sessão real e DB fictício nas duas resoluções, autosave/undo/409/importação/conferência/fechamento/Excel/reabertura.

Rollback: reverter segurança/frontend juntos na branch, mantendo evidências novas e schema 19. Reverter CORS/autorização reduz proteção e não deve ser usado para ampliar exposição. Não publicar em rede nem habilitar múltiplos workers sem desenho próprio. Nenhuma operação em DB/uploads reais foi feita.
